## 1. 架构设计

### 1.1 设计原则与规模匹配

本软件面向单机、离线、批量长视频高光剪辑与结构化JSONL结果生成，采用**经典分层架构结合模块化组件设计**。不采用分布式微服务、消息队列、服务注册发现等超出选题规模的组件。各层通过明确接口和数据模型交互；核心算法引擎层支持在不改变上层流程的前提下替换底层开源多模态模型；GUI与CLI共享同一任务服务层，避免两套逻辑。

### 1.2 需求基线与术语

* 需求基线：完全继承并对齐《通用高光视频剪辑软件需求分析文档》；项目初步设想作为背景来源。
* `frame`：原视频显示帧号，默认0-based，合法范围`[0, total_frames - 1]`；采样帧必须映射回原视频显示帧号后再输出。
* `targetRatioWH`：目标画幅比例，格式`[w, h]`，当前支持`[16, 9]`与`[9, 16]`。
* `bbox`/构图框：三元组`[x, y, w]`，`x, y`为裁剪框左上角坐标，`w`为宽度，均以原视频显示分辨率为基准；输出浮点数保留2位小数。
* `h`：裁剪框高度，不输出；由系统与评测程序按`h = w × target_h / target_w`计算，内部裁剪时四舍五入取整，最小为1像素。
* `output_mode`：默认`highlight_only`，仅输出高光帧；可选`all_frames`，用于要求全帧输出时切换。
* 运行时功能：交付软件在推理/导出阶段执行、用户可感知的功能。
* 开发流程功能：仅模型训练/偏好对齐阶段使用、不随交付软件运行的功能。

## 2. 模块设计

系统划分为5个核心算法/数据模块，并增加1个表现层交互与任务控制模块。核心模块边界清晰、职责单一；表现层模块仅封装CLI/GUI能力，不改变核心JSONL语义。

| 模块                                              | 职责                                                                                           | 边界与输入输出                                                                            | 依赖            | 对应需求               |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------- | ------------------ |
| 模块1 `Ingest & Validation Module`                | 读取输入JSONL，校验`video_id`、`video_path`、`targetRatioWH`、可选元数据、文件存在性；对缺失字段、非法比例、文件不存在记录错误码并跳过当前视频 | 输入：input_jsonl、video_root；输出：TaskSpec列表或ValidationError                            | 文件系统、数据模型     | F-01               |
| 模块2 `Sampling & Decoding Module`                | 高效解码长视频，处理旋转元数据，执行均匀采样或智能采样；智能采样失败时降级为均匀采样；采样帧映射回原视频显示帧号                                     | 输入：video_path、sample_mode、sample_fps、max_frames_per_video；输出：FramePacket列表         | 解码库、存储层       | F-02               |
| 模块3 `Multimodal Inference Module`               | 综合画面内容、事件节奏、镜头变化、音频线索和视觉质量，筛选高光帧；支持片段聚合、最短/最长片段时长、相邻重复片段去重                                   | 输入：FramePacket列表、targetRatioWH、batch_size；输出：RawPrediction列表                       | 本地多模态模型、GPU   | F-03               |
| 模块4 `Aesthetic Bbox & Scaling Module`           | 为高光帧生成推荐构图框`[x,y,w]`；结合targetRatioWH换算并校验h；无明确主体时输出整体或最大内接目标比例区域；多主体定义主主体选择规则；输出前时序平滑        | 输入：RawPrediction、VideoMeta、targetRatioWH；输出：Prediction列表                           | 模块3输出、模块5校验接口 | F-04、F-06          |
| 模块5 `Post-processing & Output Module`           | 边界检查、NaN过滤、重复frame保留首次、按frame升序排序、Schema校验、临时文件+原子替换写入JSONL；处理空predictions与allow_empty       | 输入：video_id、Prediction列表、VideoMeta、output_mode、allow_empty；输出：ExportResult和输出JSONL | 文件系统、数据模型     | F-07、F-08；F-09导出支撑 |
| 模块6 `CLI/GUI Interaction & Task Control Module` | CLI参数解析；本地Web GUI G1～G7页面；任务开始/取消/失败重试/断点续跑；生成等效CLI命令与配置快照；日志与错误中心；预览与片段选择导出                 | 输入：用户操作、配置文件、JSONL/视频目录；输出：任务、状态、预览、导出结果                                           | 应用服务层、模块1～5   | F-10～F-16、F-09     |

耦合说明：应用服务层只调用模块公开接口；模块3不直接写文件；模块4不改变frame语义；模块5是输出合法性的最后防线；模块6不得绕过模块5直接写JSONL。模块3的底层模型可通过配置替换；模块4的分割/美学模型为可插拔组件。

## 3. 关键流程与状态设计

### 3.1 批量长视频高光剪辑与JSONL生成主流程

```text
调用方/CLI/GUI     应用服务层             模块1/2/3/4              模块5后处理
   |                  |                       |                       |
   |--提交参数+JSONL->|                       |                       |
   |                  |--load_and_validate--->|                       |
   |                  |<--TaskSpec列表/异常---|                       |
   |                  |--sample_frames------->|                       |
   |                  |<--FramePacket列表-----|                       |
   |                  |--predict_frames------>|                       |
   |                  |<--RawPrediction列表---|                       |
   |                  |--generate_bboxes----->|                       |
   |                  |<--Prediction列表------|                       |
   |                  |--validate_dedupe_sort_export----------------->|
   |                  |<--ExportResult(合法数/过滤数/输出路径)---------|
   |<--日志+输出JSONL-|                       |                       |
```

数据读写对应：模块1读输入JSONL和视频元信息；模块2读视频文件并处理旋转元数据；模块3读本地模型权重并写内存结果；模块4读RawPrediction和VideoMeta；模块5写输出JSONL、错误日志和任务状态；模块6读写GUI任务状态、配置快照和等效CLI命令。

### 3.2 路径覆盖

| 路径类型        | 触发条件                            | 处理过程                                                    | 输出                                       |
| ----------- | ------------------------------- | ------------------------------------------------------- | ---------------------------------------- |
| 正常路径        | JSONL合法、视频可解码、模型输出有效            | 校验→采样→推理→构图→后处理通过                                       | 写入含有效predictions的JSONL                   |
| 分支路径：无高光    | 模型输出空列表                         | `allow_empty=true`时后处理放行空列表；`false`时跳过并记录`E_EMPTY_PRED` | `{"video_id":"...","predictions":[]}`或跳过 |
| 分支路径：部分预测无效 | frame越界、bbox越界、NaN、w<=0、重复frame | 模块5按异常矩阵处理：丢弃/修正/保留首次                                   | 仅写合法预测；记录过滤计数和错误码                        |
| 分支路径：全帧输出   | `output_mode=all_frames`        | 对要求帧输出预测；仍执行合法性校验                                       | 合法JSONL                                  |
| 异常路径：视频损坏   | 解码抛出`E_VIDEO_DECODE`            | 应用服务层记录，跳过当前视频                                          | 不中断批量；状态SKIPPED/FAILED                   |
| 异常路径：超时     | 超过`timeout_per_video`默认30min    | 终止该视频，记录`E_VIDEO_TIMEOUT`                               | 批量继续                                     |
| 异常路径：OOM    | 推理显存不足                          | 降级采样或缩短片段后重试一次；仍失败则跳过并告警`E_OOM`                         | 进程不崩溃                                    |
| 异常路径：输入非法   | JSONL缺字段、targetRatioWH非法、文件不存在  | 模块1记录错误码并跳过当前视频；配置非法则`E_CONFIG_INVALID`启动终止             | 错误日志/退出码                                 |
| GUI异常：路径非法  | 路径不存在/无权限/非视频目录                 | GUI即时提示，禁止启动                                            | 当前操作阻止                                   |

### 3.3 任务状态变化

| 状态             | 进入条件                          | 主要动作                  | 下一状态                          |
| -------------- | ----------------------------- | --------------------- | ----------------------------- |
| RECEIVED       | 读取到TaskSpec或GUI提交任务           | 参数校验                  | VALIDATED / FAILED            |
| VALIDATED      | 输入合法                          | 解码采样                  | DECODING                      |
| DECODING       | 视频可打开                         | 生成FramePacket，处理旋转元数据 | INFERRING / SKIPPED / TIMEOUT |
| INFERRING      | 帧包非空                          | 多模态推理                 | SCALING / FAILED / TIMEOUT    |
| SCALING        | 得到RawPrediction               | 生成并校验Prediction，时序平滑  | POSTPROCESSING                |
| POSTPROCESSING | 预测列表可处理                       | 过滤、去重保留首次、排序、Schema校验 | EXPORTED / EMPTY              |
| EXPORTED       | JSONL原子写入成功                   | 统计与日志                 | 成功                            |
| EMPTY          | 空predictions且allow_empty=true | 写入空列表                 | 空结果                           |
| SKIPPED        | 解码失败、空结果不允许、不可恢复异常            | 记录错误码                 | 结束                            |
| TIMEOUT        | 超过timeout_per_video           | 记录`E_VIDEO_TIMEOUT`   | 结束                            |
| FAILED         | 致命配置/模型加载失败或OOM重试失败           | 记录错误码                 | 结束或终止批次                       |

断点续跑：中断后重启，已成功且校验通过的`video_id`跳过，不重复处理；失败项可重试，成功项不重复处理。GUI运行中关闭页面需提示任务运行中，重新打开可从本地任务状态恢复进度展示。

### 3.4 异常与故障处理设计

| 故障模式          | 检测点/模块      | 处理路径                                                                      | 恢复策略        | 输出保证                          |
| ------------- | ----------- | ------------------------------------------------------------------------- | ----------- | ----------------------------- |
| 视频解码失败/文件损坏   | 模块2         | 记录`E_VIDEO_DECODE`，跳过当前视频                                                 | 批量继续        | 不生成非法预测                       |
| 单视频超时         | 应用服务层/模块2/3 | 超过`timeout_per_video`终止该视频，记录`E_VIDEO_TIMEOUT`                            | 批量继续        | 不写半成品                         |
| frame越界或负数    | 模块5         | 丢弃该帧，记录`E_FRAME_OOB`                                                      | 保留其他合法帧     | frame满足0≤frame≤total_frames-1 |
| 重复frame       | 模块5         | 保留首次出现，后续丢弃并记录`E_DUPLICATE_FRAME`                                         | 去重后升序       | frame唯一且升序                    |
| w<=0、NaN或非法数值 | 模块5         | 丢弃该帧，记录`E_BBOX_INVALID`                                                   | 保留其他合法帧     | 不写NaN/Infinity/w<=0           |
| bbox越界        | 模块5         | 优先平移；无法平移则等比缩小；仍不满足`min_bbox_size`或h<1则丢弃，记录`E_BBOX_OOB`/`E_BBOX_INVALID` | 保留可修正预测     | 输出框满足x≥0,y≥0,w>0,x+w≤W,y+h≤H  |
| 空predictions  | 模块5         | `allow_empty=true`输出空列表；`false`跳过并记录`E_EMPTY_PRED`                        | 按配置         | JSONL合法                       |
| GPU OOM       | 模块3         | 捕获OOM，降级采样或缩短片段后重试一次；仍失败跳过并告警`E_OOM`                                      | 批量继续        | 进程不崩溃                         |
| 模型加载失败        | 应用服务层       | 致命错误，记录`E_CONFIG_INVALID`或启动失败原因，终止批次                                     | 用户修复模型路径/显存 | 不写半成品                         |
| 配置非法          | 启动校验        | 终止启动并输出`E_CONFIG_INVALID`                                                 | 用户修正配置      | 不启动                           |
| GUI路径非法       | 模块6         | 即时提示，禁止启动                                                                 | 用户修正路径      | 当前操作阻止                        |
| 输出写入失败        | 模块5         | 记录`E_CONFIG_INVALID`或输出错误；临时文件不替换正式文件                                     | 用户检查磁盘/权限   | 已导出JSONL不损坏                   |

越界裁剪策略对齐需求分析文档4.3：设显示宽高`W,H`，目标比例`target_w:target_h`，候选框`[x,y,w]`，`h=round(w×target_h/target_w)`。优先平移：若`w<=W`且`h<=H`，将`x`限制在`[0,W-w]`，`y`限制在`[0,H-h]`；再等比缩小：若`w>W`或`h>H`，令`scale=min(W/w,H/h)`，更新`w=w×scale`，重算`h`，再平移；最小尺寸检查：修正后`w<min_bbox_size`或`h<1`，丢弃并记录`E_BBOX_INVALID`；无主体默认框：输出最大内接目标比例区域，无法确定时输出以画面中心为中心的最大内接区域。

#### 4.3.3 输出JSONL接口

示例：

```json
{"video_id":"v_001","predictions":[{"frame":10,"bboxes":[120.0,80.0,40.0]}]}
{"video_id":"v_002","predictions":[]}
```

字段约束：`video_id`与输入一致；`predictions`按`frame`升序且不重复；`frame`为0-based原视频显示帧号，非负整数且小于总帧数；`bboxes`为`[x,y,w]`浮点数，统一保留2位小数，`x>=0,y>=0,w>0`，换算后不越界；高度不输出，由系统与评测程序按公式计算；无高光时按`allow_empty`输出空列表或跳过并记录`E_EMPTY_PRED`；输出采用临时文件+原子替换，避免半行JSONL。

### 5.3 一致性策略

- 空间一致性：输出`[x,y,w]`以原视频显示分辨率为基准，读取视频时处理旋转元数据；换算`h`后必须满足`x+w≤W`、`y+h≤H`；否则按“平移→等比缩小→最小尺寸丢弃”处理。
- 时序一致性：同一视频`frame`不重复，按升序输出；重复时保留首次出现，后续丢弃并记录`E_DUPLICATE_FRAME`。
- 类型一致性：输入/输出JSONL禁止NaN、Infinity；`x,y,w`输出浮点数保留2位小数；数值字段必须为JSON数值。
- 接口/界面一致性：CLI、GUI、JSONL均使用`video_id`、`video_path`、`targetRatioWH`、`output_path`；输出仅含`video_id`和`predictions`，不输出内部score和h。
- 空结果一致性：`allow_empty=true`时无高光输出`predictions: []`，不视为错误；`false`时跳过并记录`E_EMPTY_PRED`。
- GUI/CLI一致性：同一输入、同一配置下GUI导出JSONL与CLI导出JSONL语义一致；GUI不改变坐标规则和异常处理规则。

### 5.4 错误码与内部映射

对外用户可见错误码严格采用需求分析文档2.4：

| 错误码                 | 含义                                | 默认处理                     |
| ------------------- | --------------------------------- | ------------------------ |
| `E_VIDEO_DECODE`    | 视频解码失败或文件损坏                       | 跳过该视频，记录日志，批量继续          |
| `E_VIDEO_TIMEOUT`   | 单视频处理超时                           | 终止该视频，记录日志，批量继续          |
| `E_EMPTY_PRED`      | 输出predictions为空且allow_empty=false | 跳过该视频并告警                 |
| `E_FRAME_OOB`       | frame越界或为负                        | 丢弃该帧并记录                  |
| `E_BBOX_OOB`        | bbox坐标越界                          | 按4.3越界策略修正；无法修正则丢弃该帧     |
| `E_BBOX_INVALID`    | w<=0、NaN或非法数值                     | 丢弃该帧并记录                  |
| `E_DUPLICATE_FRAME` | 重复frame                           | 保留首次出现，后续重复丢弃并告警         |
| `E_OOM`             | 显存不足                              | 降级采样或缩短片段后重试一次；仍失败则跳过并告警 |
| `E_CONFIG_INVALID`  | 配置缺失或非法                           | 启动阶段终止并输出明确错误            |

内部可细分日志原因，但GUI错误中心与用户可见错误必须映射到上述错误码，不得出现未定义错误码。

## 8. 设计决策与权衡

1. 构图框输出采用三元组`[x,y,w]`，高度由后处理与评测程序按`h=w×target_h/target_w`换算。需求分析文档已明确统一由系统与评测程序推导高度，避免多模型高度标准不一致。
2. 推理采用本地开源多模态模型，不调用商业闭源云端API。依据为需求分析文档的离线运行、数据隐私、可复现性和合规约束。
3. 架构采用单机分层+模块化组件，不采用分布式微服务。批处理离线软件规模有限，分布式会引入不必要的运维复杂度。
4. 后处理采用“修正优先、过滤兜底、空列表按配置放行”的策略；越界按“平移→等比缩小→最小尺寸丢弃”；重复frame保留首次出现，符合需求分析文档4.2/4.3。
5. 输出模式默认`highlight_only`，支持`all_frames`切换；片段聚合仅用于预览与物理导出，不改变JSONL默认语义。
6. GUI作为CLI封装，必须生成等效CLI命令与配置快照；GUI不改变JSONL语义、坐标规则和异常处理规则，保证可复现与格式验收一致。
7. 错误码对外严格采用需求分析文档2.4；内部日志可细分原因，但用户可见错误必须映射到已定义错误码，避免未定义错误码。
