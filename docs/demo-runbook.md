# 现场演示：网页到远程 F1

更新：2026-11-27。本轮定位为受信任课堂演示；B维护启动/环境，D完善模式显示，A/E完成媒体/恢复验收，详见[四人计划](FINAL_IMPROVEMENTS_PLAN_20261125.md)。保存配置的启动器已支持远端离线时继续使用本机网页。

使用 SSH 加密连接把远程回环服务映射为本机网页。适用于算家交互式服务器选择入口，不依赖网关支持 TCP 端口转发。浏览器无需安装 SSH 插件，也不会接触服务器密码。

## 准备一次

### 已保存的服务器（推荐）

当前连接已保存在 [`config/demo.json`](../config/demo.json)：`connect.westb.seetacloud.com:28612`，用户 `root`，部署目录 `/root/autodl-tmp/highlight-studio/f1/demo-20261106`。这些是连接参数，不含密码或私钥。

本机 OpenSSH 中的 `highlight-studio-gpu` 别名应与该配置一致，并使用自己的密钥登录。已有免密登录可直接复用；首次准备登录时确认服务器指纹，将密钥配置在本机 SSH 中。启动器核对别名目标，避免无意连接其他服务器。

Windows 双击仓库根目录 `Start-Demo.cmd`，或运行：

```powershell
.\Start-Demo.ps1
```

启动器先启动本机网页，再在后台连接服务器，不等待远程就绪；再次启动会复用已有本机服务并尝试重连。其他系统可运行 `python scripts/start_demo.py` 并保持终端开启。两种方式均读取保存的配置，无需逐次填写服务器参数。网页与基础演示只需 Python 标准库；远程处理需要系统 OpenSSH 及有效认证，完整本机媒体模拟另需 `requirements-dev.txt` 与 FFmpeg/FFprobe。

本机网页地址为 http://127.0.0.1:18000。页面、样式和脚本读取本地产品代码，更新本机前端后刷新即可生效。连接成功且远程分析服务就绪时，“云端处理”可用，所选视频与任务经 SSH 到已有部署。连接中或失败时该选项置灰，空工作区默认选择本机演示，仍可导入、预览和操作模拟任务。

本机演示数据单独保存在被忽略的 `runtime/gpu-demo/local/`。完整 CPU 媒体依赖可用时自动使用模拟片段与成片流程；缺少 FFmpeg/FFprobe 或 Pillow 时自动使用基础空 Mock，页面解释不会生成高光片段。所有演示结果持续标记为模拟。旧的真实任务仍只向远端查询，断线时明确提示恢复失败；切换到演示不会替它生成模拟结果。技术细节见[离线启动初稿](changes/2026-11-27-offline-startup.md)。

服务器地址或部署路径变化时更新上述配置一次，同时使本机 SSH 别名与配置一致。点击网页右上角“重新检查连接”，或再次双击启动入口；重连会重新读取保存配置。修改 `local_port` 则需先停止原启动器再重启，因为它决定本机网页监听端口。GPU 未开启或登录失败时查看 `runtime/gpu-demo/launcher.stderr.log`，本机网页继续运行。模型与运行环境仍复用服务器上已有的部署。

### 其他服务器与交互式网关

本机安装 Python 3.11+，拉取 main，运行：

```sh
python -m pip install -r requirements-demo.txt
```

远程保持已验收的 candidate-v0 布局：app、assets、.venv-f1、.venv-mock、mock-service.sh、sj-f1-service.sh，以及 gpu-runtime/de-service/acceptance-dir.txt 指向的真实产品验收目录。将当前版本的 app/scripts 和 app/apps/frontend 同步到部署目录；不要覆盖权重、模型配方或验收目录。现有服务每次请求读取网页文件，不必为页面更新中断任务。

## 每次演示

在平台选择有 GPU 的实例开机，然后在本机项目目录运行（用自己的 SSH 地址和用户名）：

```sh
python scripts/connect_demo.py --host <SSH主机> --user <SSH用户名> --ssh-port 2020 --instance 0 --remote-root /root/sj-fs/highlight-studio/f1/candidate-v0 --mode real
```

按提示输入密码。首次连接新主机需核对 SSH 指纹并确认；已有 known_hosts 中的主机密钥不匹配时拒绝连接。连接器不会保存密码或自动开通付费 GPU。保持该终端开启，浏览器打开 http://127.0.0.1:18000 。页面显示“服务已连接”，云端处理可用，上传视频后开始分析。建议自行准备有权使用的短视频，既有12秒样片的分析约90秒，以实际任务状态为准。

无显卡时把 `--mode real` 改为 `--mode mock`，可以演示上传、任务、片段编辑、预览与下载，页面会明确标记模拟。真实模式缺少 GPU 时直接拒绝启动，不降级成模拟。

直接 SSH 登录的 GPU 主机不需要 `--instance`。若系统未安装 `/usr/bin/python3`，用 `--remote-python` 指定已有解释器，例如 `--remote-python /root/miniconda3/bin/python`。可通过 `--port 18002` 与原服务器的本机演示端口区分。远程启动脚本仍需按该机器的推理环境、FFmpeg 和已验收配置部署。

## 验证顺序

1. 页面确认引擎和远程状态，选一个有权使用的含音频 H.264 CFR MP4。
2. 分别选择9:16或16:9，上传并等待任务成功。
3. 预览裁剪，调整片段起止时间，点击应用修改。
4. 生成MP4并下载，检查画幅和音频；必要时另导出JSONL。
5. 刷新页面，从记录恢复任务，再下载已有成片。

素材限制沿用媒体规范：不超过512 MiB、10分钟、4K、120fps，无旋转且音视频从零开始。固定/变帧率均可通过准入；变帧率暂用平均帧率时钟，音画同步与精确时间映射未处理。真实模型可能选帧为空，界面应保留空结果，而不是伪造高光。

## 故障与恢复

- `GPU_NOT_READY`：平台仍为无卡模式，切换GPU后重新连接。
- `CUDA_NOT_READY`：检查远程.venv-f1和驱动；不要用模拟结果替代真实结果。
- 已保存启动器远程连接失败：本机页面仍可用，云端入口显示“未连接”。更新配置或恢复服务器后点击“重新检查连接”。缺少本机 SSH、别名不匹配、认证失败或服务器未启动均按远程不可用处理，详细原因看本机日志。
- 远程启动超时：查看gpu-runtime/de-service/server.log。首次启动可能校验模型资产，远程连接最多等待240秒；保存配置的启动器不会因此阻拦本机页面。
- 连接中断：已保存启动器保留网页，重新检查连接后从任务记录恢复；旧交互式 `connect_demo.py` 则重新执行相同命令，保持相同本机端口。已经完成的服务端结果不会因为连接器退出而删除。
- 本机页面未启动：检查 Python 环境、配置 JSON、本机端口冲突和 runtime 日志；这些是本机错误，不能用远端离线模式掩盖。
- 上传中断：重新选择视频并上传；不要把未完成上传视为任务成功。

连接器仅绑定本机127.0.0.1，拒绝不匹配的Host及跨源请求，不是公开多用户网关。单条SSH连接按顺序转发请求，适合单人课程演示；没有增加并行GPU推理能力。平台关机或切换实例会中断SSH，已保存启动器可在网页重新检查连接。真实F1模型仍使用已验收配置，不重新下载模型、不启动训练、不改动比赛代码。

连接器提供可选的GET `/api/v1/deployment`，契约见`contracts/deployment.schema.json`。普通本机服务返回404时，前端继续沿用本机行为。模拟与真实远程任务在浏览器中分开存储，避免切换模式后恢复另一套服务的任务。SSH载荷采用分块Base64，避免交互式网关改写二进制视频；最终HTTP响应仍保留原文件字节和Range语义。
