# 05 非功能需求与验收计划（初稿）

[返回需求文档导航](README.md) · [上一篇：数据与接口](04-data-and-interfaces.md)

## 1. 非功能需求

下表为拟定的产品验收要求或目标。尚未进行真实模型、媒体或性能验收，不能将这些数值写成当前系统已经达到的指标。

| 编号 | 质量属性 | 要求或建议目标 | 验证方法 |
|---|---|---|---|
| NFR-01 | 媒体正确性 | 保留帧与编辑方案一致；目标比例正确；导出时长与启用区间总时长误差不超过 `max(1/fps, 0.10秒)`；同步标记的音画偏差不超过 100 ms | 用带烧录帧号、彩色区域和同步声画标记的测试素材，核对首末帧、裁剪、时长及音轨 |
| NFR-02 | 交互响应 | 同机开发环境、5 个并发状态查询下，创建任务/查询状态 API 的 p95 目标不超过 500 ms；不含上传、素材校验、推理、编码及跨公网传输；前端操作应立即给出反馈 | 记录机器、版本、样本量；持续测量至少 100 次有效请求，报告实际值 |
| NFR-03 | 可靠性 | 已成功保存的方案在刷新或服务重启后仍可读；任务有明确终态或受控排队状态；文件不完整不得下载；手动重试不覆盖原记录 | 重启、进程中断、磁盘不足及结果写入失败的故障注入 |
| NFR-04 | 文件与访问边界 | 输入和下载均通过受控编号；校验内容和大小；禁止任意路径读写；部署按单一受信任工作区开放；原片默认不外传第三方 AI 服务 | 目录穿越、伪造类型、跨项目关联、超限上传、删除归属测试及部署配置检查 |
| NFR-05 | 可用性与可访问性 | 中文主流程；错误有下一步；状态不只靠颜色；主要操作可用键盘完成，输入有名称；不展示虚构进度；未保存离开有提示 | 人工走查；至少 3 名目标使用者尝试主流程并记录卡点，结果不作统计泛化 |
| NFR-06 | 可维护性与可追溯性 | 前后端按契约联调；比赛依赖仅经适配层进入；每次分析和导出能追溯代码/模型/素材/编辑版本；需求变更同步验收项 | 代码依赖检查、版本记录抽查、契约测试 |
| NFR-07 | 资源与执行边界 | 分析并发默认 1、导出默认 1；有磁盘检查和有限超时；失败清理临时文件；模型不可用时明确拒绝；不自动训练或下载权重 | 并发请求、超时、空间不足、模型缺项测试；记录峰值显存与处理耗时 |
| NFR-08 | 兼容性与可部署性 | 在团队选定并记录具体版本的桌面 Chrome/Edge 中完成上传、预览与下载；部署说明列出 Python、媒体工具、模型资产和启动方式 | 新环境按说明复现一次；记录浏览器、操作系统、GPU 与软件版本 |

真实推理延迟与 GPU 显存需求目前未知。应至少对 15、60、180 秒三个有效新视频记录上传、分析、导出的分项耗时及峰值资源；若某档超出设备能力，应降低并公开配置上限，不能承诺“实时”或无依据的秒级完成。

## 2. 验收样本与环境

| 样本组 | 建议内容 | 用途 |
|---|---|---|
| S1 基础有效素材 | 横屏/竖屏、24/25/30 fps、短片、有声与无声 | 上传、帧时钟、模型与导出 |
| S2 确定性媒体夹具 | 烧录原帧号、边缘彩块、明确闪光和音频脉冲；配人工构造预测 | 精确检查帧选择、裁剪边界和音画同步；不用于宣称模型效果 |
| S3 边界/异常素材 | 超时长/大小/尺寸、损坏、伪装扩展名、变帧率、旋转元数据 | 校验与错误处理 |
| S4 模型返回夹具 | 空列表、单帧、多个不连续段、重复帧、NaN、越界框、源身份不符 | 适配契约与结果校验 |
| S5 真实新视频 | 约 5～10 个有权使用、覆盖目标场景的视频，至少包含横竖构图和运动主体 | 端到端可用性与人工质量记录；不读取旧比赛预测替代推理 |

S2/S4 是软件正确性测试数据，应清楚标记构造来源。真实模型验收只使用 S5 等真实执行记录，不能将模拟/夹具结果计入 AI 成功率。素材与运行产物放在仓库外或被忽略的运行目录，仅提交生成方式、摘要和不含私有媒体的报告。

## 3. 验收场景与需求追踪矩阵

**状态说明：下列 AT 项均为计划，当前未执行。** 本次文档检查和已有模拟接口检查通过，不代表这些产品功能已通过验收。

| 编号 | 场景与操作 | 通过条件 | 覆盖需求 |
|---|---|---|---|
| AT-01 | 新建项目，上传有效视频，刷新项目详情 | 名称、稳定编号、素材元数据正确；原文件摘要保持；刷新仍存在 | FR-01、FR-02；NFR-03 |
| AT-02 | 上传伪装 MP4、损坏或超限文件；中途断开 | 后端给出对应错误；不建立有效素材/分析任务；临时文件可清理 | FR-02；NFR-04、NFR-07 |
| AT-03 | 上传变帧率、有旋转元数据及未经支持的编码 | 按初稿媒体范围明确拒绝；不悄悄套用错误帧/坐标基准 | FR-02；BR-01；NFR-08 |
| AT-04 | 对新视频运行固定真实模型 | 记录源摘要和实际模型版本；适配器返回 `mock=false` 的合法结果；已有模拟模式不可当作真实验收 | FR-03；BR-02；NFR-06 |
| AT-05 | 双击提交，使用相同/不同幂等键并发发起；查询状态 | 同键同内容返回同一任务；同键异内容或项目同类活跃任务冲突；全局分析并发受限；状态如实变化 | FR-03、FR-04、FR-13；BR-08；NFR-02、NFR-07 |
| AT-06 | 输入合法的多段/单帧构造预测 | 生成最大连续帧段；空隙不补入；单帧不丢；时间按正确 fps 计算 | FR-05；BR-03；NFR-01 |
| AT-07 | 分别返回合法空列表、模型异常、非法/重复/越界预测 | 空列表成功但无建议且禁止导出；其余失败；不以空成功结果掩盖错误 | FR-05；BR-02；NFR-03 |
| AT-08 | 在横竖画面、播放器缩放和留白下检查自动裁剪 | 框定位正确；模型变宽轨迹可预览；虚构置信度不显示；错误预览有提示 | FR-05、FR-08；BR-04；NFR-01、NFR-05 |
| AT-09 | 取消/恢复片段，调整起止到帧边界，尝试越界/重叠 | 启用片段顺序正确；无重复帧；非法调整拒绝；源与模型结果未变 | FR-06、FR-07；BR-03；NFR-01 |
| AT-10 | 全部取消并保存；恢复原建议；用旧基础版本保存 | 空方案能保存不能导出；恢复需确认且绑定正确分析；过期保存返回冲突；未保存离开提示 | FR-06、FR-07、FR-09；BR-07；NFR-05 |
| AT-11 | 扩展片段，导出多段有声/无声视频并下载 | 扩展框来自对应建议边界；视频、原声按同区间剪切；无声输入正常；尺寸和时长符合 NFR-01 | FR-07、FR-08、FR-10、FR-11；BR-04～BR-06；NFR-01 |
| AT-12 | 版本 1 开始导出期间保存版本 2；重新分析并选择采用新结果 | 第一次导出仍对应版本 1；版本 2 与新分析不会覆盖旧结果、方案或成片；未保存内容不会混入导出 | FR-03、FR-09、FR-10；BR-07；NFR-06 |
| AT-13 | 关闭/刷新页面，重启服务后查看项目与已保存编辑 | 项目、结果、方案、导出记录保留；不会因读取创建新任务 | FR-01、FR-04、FR-09、FR-12；NFR-03 |
| AT-14 | 中断运行中的分析/导出，再启动服务并手动重试 | 确认旧进程退出后将中断任务记失败；队列项校验后恢复；新任务记录 `retry_of`；旧文件不冒充成功 | FR-04、FR-10、FR-12、FR-13；BR-08；NFR-03、NFR-07 |
| AT-15 | 请求非法路径、错属项目的结果/导出，移除一个成片文件后下载 | 不读取范围外文件；项目关联校验失败；缺文件明确不可用；错误不泄漏路径或凭据 | FR-11、FR-14；BR-09；NFR-04 |
| AT-16 | 模型缺项、资源不足、超时及渲染失败 | 错误码与用户提示对应；有诊断编号；不会无限重试、自动换模型或生成假成功 | FR-04、FR-13；NFR-03、NFR-07 |
| AT-17 | 删除有活跃任务/无活跃任务的项目；在清理中断后重试 | 活跃时拒绝；无活跃时阻止新任务和下载后清理；中断可追踪；其他项目与模型文件保持 | FR-14；BR-09；NFR-03、NFR-04 |
| AT-18 | 在选定浏览器播放原片/成片并跳转；执行性能和用户走查 | 支持媒体分段读取；成片可播放/下载；记录 p95、资源与用户卡点；达到确认后的 NFR 目标 | FR-08、FR-10、FR-11；NFR-01、NFR-02、NFR-05、NFR-08 |
| AT-19 | 仅在选择交付 P1 时：固定裁剪、新增片段、第二画幅、单段导出 | 新增能力具有边界校验、版本记录及实际媒体验证；未交付项不显示可用入口 | FR-15（P1） |

真实模型至少完成一个“上传新视频 → 真实预测 → 用户修改 → 成片下载”的全流程。S2/S4 的媒体与契约检查不能替代这项要求。

## 4. 分层测试建议

| 层次 | 应测试的外部行为 | 不应当作完成证据的内容 |
|---|---|---|
| 纯规则 | 连续帧分组、时间换算、裁剪边界、重叠检查、编辑版本冲突 | 只验证函数被调用，未核对输出 |
| 业务接口 | 上传失败不入库、创建/查询/重试、幂等、范围内文件访问 | 只测 HTTP 200，不看业务状态 |
| 执行与恢复 | 单执行者领取、有限超时、失败保留、重启恢复、产物发布 | 内存模拟队列长期充当持久化证明 |
| 媒体集成 | 指定片段、动态裁剪、公共尺寸、音轨、下载文件实际可解码 | 只存在一个 MP4 文件，未检查内容 |
| 真实端到端 | 固定模型处理新输入，并生成可修改与下载的成片 | 旧比赛 JSONL、mock 或手工结果冒充推理 |
| 用户走查 | 用户独立完成主流程，能理解状态和错误 | 开发者只展示一条预先准备好的成功动画 |

既有 `scripts/check_repository.py` 验证仓库引用与边界；`scripts/smoke.py` 验证模拟 HTTP 契约。两项应继续保留，但不替代上表新增能力的验收。

## 5. 交付完成定义

首版宣布完成前，应满足：

1. P0 功能对应的 AT-01～AT-18 均有执行记录；阻断上传、分析、编辑或导出的缺陷已解决。
2. 至少一种目标比例在新视频上通过真实模型和媒体导出验收。
3. 需求、实际接口和界面一致；未实现的 P1 不混入必备路径或演示承诺。
4. 部署环境、模型资产指纹、配置、支持的输入范围已记录；可按说明复现。
5. 测试报告列出通过、失败、未执行项及证据位置；不把尚未完成的项目标成通过。
6. 用户能清理项目文件；演示环境不存在因中断永久占用的任务或不可追踪的大文件。

建议的验收记录字段：`AT编号 / 产品提交 / 比赛提交 / 模型版本 / 环境 / 样本摘要 / 步骤 / 实际结果 / 结论 / 证据位置 / 执行人 / 日期`。证据中的媒体与机器敏感路径不上传 Git。

## 7. 风险与应对

| 风险 | 早期信号 | 应对与范围调整 |
|---|---|---|
| 高分成果只在旧缓存上可回放 | 新视频无法得到完整预测 | 第一个里程碑即验证；选择能够完整运行且已验证的固定版本，明确质量差异 |
| 模型耗时或显存超出预期 | 180 秒样本无法完成或频繁 OOM | 实测并降低输入上限；排队与并发限制公开；不无依据承诺实时 |
| 逐帧预测转成片时帧/音频错位 | 输出时长、边界或嘴型不同步 | 先用确定性媒体夹具验证 BR-01～BR-06，再接真实模型 |
| 功能范围不断扩大 | 引入多轨、字幕、登录等并拖慢主流程 | 维持 P0/P1 列表；新增需求写明替换哪项排期 |
| 课程用户不理解 AI 结果 | 片段碎、主体裁错、缺少修正入口 | 保留人工时间微调与原片对比；记录误差，不用评分冒充体验 |
| 任务或文件状态不一致 | 已显示完成却没有文件；重启后永久执行中 | 原子发布、终态校验和中断恢复；失败保持可追踪 |
