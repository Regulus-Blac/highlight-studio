## 2. NFR执行口径

| 编号 | 本轮要求 |
|---|---|
| NFR-01 媒体正确性 | 双画幅、已应用方案、源帧/框/比例一致，声音按同区间；用可识别夹具核实，不只看文件存在 |
| NFR-02 响应与性能 | 页面立即显示真实状态；上传、排队、推理、导出分别计时，不承诺500ms/实时；保留实测环境与样本 |
| NFR-03 可靠性 | 幂等、刷新重连、重启中断记失败、手动重试、不可下载半文件；不宣称中断续算 |

| NFR-08 部署 | 普通电脑模拟、既有GPU远程真实两条路径清楚；记录Python/媒体工具/浏览器，缺项有建议 |

## 3. 样本与验收范围

A准备3～5个授权/自有短样例，覆盖横/竖构图、有声/无声与损坏/不支持输入。真实模型复验优先10～30秒CFR H.264样片，双画幅有限执行；合成视频用于帧/框/音轨确定性检查。素材放runtime或外部目录，不进Git。

保留旧AT编号追溯：AT-02～AT-09、AT-11、AT-14～AT-16、AT-18中适用于v1的上传/模型/媒体/异常行为已有实现与部分证据，应按本轮改动复验；不笼统标为全部通过。AT-01项目命名、AT-10/12服务端编辑版本冲突、AT-13完整项目域、AT-17网页项目删除的原描述超出本轮，分别收敛为任务恢复、导出快照和演示者离线清理。AT-19扩展不阻塞P0。

最终按分工计划的9项联合清单逐项记录通过/失败/未执行。没有GPU时真实复验必须标未执行，保留历史记录，不能用mock-media代替。当前代码硬上限不是已压测规模；本轮不要求15/60/180秒或4K大批GPU测试。

## 4. 检查方式与交付

- 接口/页面：smoke、相关已有unittest、JS语法与必要浏览器走查。
- 媒体：安装FFmpeg/FFprobe和requirements-dev.txt后运行现有媒体检查；与实际MP4的内容/时长/音轨一起确认。
- 完整子模块：有读取权限的环境运行check_repository；普通产品开发不需要强制初始化。
- 真实端到端：有限新样片，记录mock=false、引擎、环境、耗时、框/帧与成片；与CPU夹具分开。
- 清理与启动：新同学按一页说明复现；dry-run默认、活跃拒绝、确认只清指定runtime。

记录字段：用例/产品提交/模型发布/输入摘要/环境/步骤/实际输出/结论/证据路径/执行人/时间。运行媒体、凭据和私有日志不进入Git。四人估时与依赖以[最终分工计划](../FINAL_IMPROVEMENTS_PLAN_20261125.md)为准，旧三周从零建设模型/网页的排期已被替换。
