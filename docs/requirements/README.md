## 一分钟读懂

用户上传一个视频，由已有模型推荐高光时间范围和画面裁剪位置；用户检查建议、调整片段后，下载带原声的成片。首版着重完成这条流程，控制功能数量，以便在较短课程周期内实现和演示。

**首版验收主线：上传新视频 → 真实模型分析 → 调整高光片段 → 预览裁剪结果 → 下载音画同步的 MP4。**

本文件夹描述的是产品需求，不代表功能已经实现。当前仓库只有模拟接口、联调页面、模型适配接口和比赛版本引用管理；模拟结果为空，不读取视频，也不生成成片。现状核对见 [产品范围](01-product-scope.md)。

## 编号与优先级

| 标记 | 含义 |
|---|---|
| `FR-xx` | 功能需求；具体行为定义在 02 |
| `BR-xx` | 业务规则；定义在 04 |
| `NFR-xx` | 非功能要求；定义在 05 |
| `AT-xx` | 验收场景；定义在 05，与需求编号对应 |
| `A-xx` / `Q-xx` | 初稿假设 / 尚待团队决定的问题；定义在 01 |
| P0 | 首版必须完成；全部相关验收通过后才能称为首版可交付 |
| P1 | P0 完成后的增强项；未实现时入口应隐藏或清楚说明 |
| 后续 | 本轮不纳入开发和验收 |

“应”“必须”表示本初稿提出的验收要求；“建议”“目标”表示待团队确认的选择或测量目标。数值限制是初稿建议值，不是实测结论或用户已经批准的承诺。

## 文档与工程的边界

- 本次仅增加需求文档与图表，现有业务实现、JSON Schema 和模型引用保持原样。
- 模型内部继续采用 [v1 契约](../../contracts/README.md)。面向真实上传、编辑和异步任务的业务接口在 04 中作为 **v2 草案**提出，尚未实现。
- 前后端通过稳定契约协作；比赛源码的导入、路径和命令转换集中在模型适配层。比赛子模块不在产品仓库中修改。
- 权重、视频、特征、运行结果和凭据保存在仓库外或被忽略的运行目录；文档图表仅含抽象流程和虚构示例。
- 需求变化应更新受影响的功能、规则、图表及验收项，避免只改图或只改某一份说明。
