# 01 产品范围与用户场景（初稿）

[返回需求文档导航](README.md) · [下一篇：功能与交互](02-functional-requirements.md)

## 1. 背景与问题

AIC 比赛项目能够输出视频高光预测：哪些原视频帧值得保留，以及每个保留帧的画面裁剪框。比赛交付以 JSONL 为主，用户仍需要理解结果、选择片段并生成视频。

软件工程项目在这些成果之上提供可操作的网页工具。用户关心的是“哪些片段值得保留”“裁剪后主体是否完整”“能否快速修改并拿到成片”，而非模型文件、命令或 JSONL 字段。

## 2. 产品目标与成功标准

| 目标 | 对用户的价值 | 如何验证 |
|---|---|---|
| G1 自动产生可用的粗剪建议 | 减少逐段查找高光的操作 | 一个新视频能生成真实模型结果，并正确展示对应源片段 |
| G2 允许用户修正建议 | 用户保留最终剪辑决定权 | 用户能够删除片段、调整起止时间、恢复原建议 |
| G3 交付可播放的视频 | 完成实际剪辑任务 | 下载的 MP4 与已确认的剪辑方案一致，保留并同步处理原声 |
| G4 形成可维护的课程项目 | 团队可分工、复现与验收 | 需求、接口、版本、测试证据和部署说明互相对应 |

首版不承诺模型理解所有视频类型，也不以比赛分数直接推断用户满意度。应固定一组有权使用的演示视频，记录成功率、处理时间、主体保留情况及用户需要的修改步骤。

## 3. 当前状态与建设缺口

| 项目 | 当前状态 | 首版需要补齐 |
|---|---|---|
| 网页 | 静态模拟联调页 | 上传、任务、剪辑与导出界面 |
| 业务后端 | 标准库 HTTP 服务；任务只存内存 | 文件管理、异步任务、持久化、业务校验 |
| 模型接入 | `MockAdapter` 返回明确标识的空结果 | 处理新视频的真实适配器和独立推理环境 |
| 数据契约 | v1 请求/逐帧预测结构已有 | 素材元数据、剪辑方案、任务与导出契约 |
| 视频生成 | 未实现 | 根据剪辑方案裁剪、拼接、处理原声并编码 |
| 比赛依赖 | 子模块固定源码提交 | 确认对应权重、环境和新视频完整推理流程 |
| 工程检查 | 仓库引用检查、模拟 HTTP 检查 | 真实功能、异常恢复、媒体一致性与性能验收 |

源码拉取、权重交接、旧预测回放和新视频端到端推理是不同完成状态。首个集成里程碑必须使用新视频验证，不以读取旧比赛结果替代。

## 4. 用户与使用环境

| 角色 | 主要诉求 | 首版权限与职责 |
|---|---|---|
| 视频使用者 | 上传自己的素材，得到建议，修改和下载 | 操作本部署中的项目与素材 |
| 课程演示者 | 稳定演示完整流程，解释失败和限制 | 使用准备好的合法素材，查看任务状态与版本 |
| 部署维护者 | 配置模型、磁盘、资源限制，处理失败 | 通过部署配置和日志管理；首版不开发管理后台 |
| 模型维护者 A/B | 提供与契约兼容的真实推理能力 | 固定并验收模型资产、适配器和运行环境 |

初稿按“单一受信任工作区”设计：一套部署由个人或知情的课程团队使用，工作区内项目可见。不含多用户隔离、注册和角色权限；不能据此把它作为匿名公网服务发布。公网或多租户需求出现时，应先补充身份与授权需求。

## 5. 首版范围

| 优先级 | 内容 |
|---|---|
| P0 | 创建项目、上传单个视频、校验素材、选择已支持的目标比例 |
| P0 | 真实模型分析、排队与阶段展示、保存和读取任务记录 |
| P0 | 高光片段列表、原画面与自动裁剪预览、片段启用/删除、起止微调、恢复建议 |
| P0 | 保存剪辑方案、异步导出、成片预览、下载、失败后手动重试 |
| P0 | 项目历史、服务重启后的状态处理、项目删除和文件清理 |
| P1 | 每段固定裁剪框的手动调整、第二种目标比例、手动新增片段、单个片段导出 |
| 后续 | 多素材、多轨时间轴、转场、滤镜、配乐、字幕、语音或自然语言编辑 |
| 后续 | 登录注册、云空间、公开分享、多人实时协作、移动端应用、支付 |
| 后续 | 新模型训练、排行榜提分、模型市场、分布式调度与弹性扩容 |

P1 不得成为 P0 的隐藏依赖。例如没有实现手动新增片段时，“无高光”应允许返回项目或重新分析，而不能要求用户靠新增片段完成流程。

## 6. 典型场景

### 场景一：完成一段高光粗剪

小林上传一段约一分钟的视频，选择当前支持的画幅。系统分析后给出几个片段。小林逐个预览，取消一个不满意的片段，把另一个片段的起点向前调整几帧。保存后发起导出，预览成片并下载。

**成功结果：**成片只包含启用的片段，按源视频时间顺序拼接，画幅正确，原声音画同步。

### 场景二：刷新页面后继续工作

小林提交分析后关闭页面，稍后重新打开项目列表。系统显示原任务的真实状态；完成后可继续编辑，尚未完成则继续等待，不重复创建同一个任务。

### 场景三：模型没有选出高光

模型成功执行，但返回空预测。界面说明“分析完成，未发现建议片段”，保留素材和分析记录，并提供返回或重新分析入口。不能显示为系统失败，也不能直接导出空视频。

### 场景四：导出时中断

导出过程中服务中断。恢复后，系统将无法继续的任务记录为失败，清楚提示可重试；已保存的剪辑方案仍可读取。用户重新导出产生新任务，失败文件不可下载。

## 8. 初稿假设与建议限制

这些值为控制开发范围提出，均需在集成阶段验证。配置改变后，上传提示、服务端校验和测试数据必须同步更新。

| 编号 | 建议假设或限制 | 理由与边界 |
|---|---|---|
| A-01 | 首版面向桌面浏览器；单一受信任工作区 | 降低账户、多端和多人协作成本 |
| A-02 | 一项目一个源视频，默认按源时间排序输出 | 不引入素材库、多轨或片段重排 |
| A-03 | 初始接收 MP4 / H.264，原声为 AAC 或无音轨 | 缩小首轮媒体兼容验证矩阵；只改扩展名不算合法 |
| A-04 | 文件不超过 500 MiB；时长不超过 180 秒；长边不超过 1920、短边不超过 1080 像素 | 属于拟定上限；不代表已测得该规模的模型性能 |
| A-05 | 首轮接收恒定 24、25、30 fps、无旋转元数据的视频；其他输入明确拒绝并说明原因 | 稳定原帧号、时间及坐标映射；变帧率和旋转规范化另行扩展 |
| A-06 | 至少交付一种实测可用的目标比例；另一种列 P1 | 9:16 / 16:9 的选项存在不代表两种模型能力均已验收 |
| A-07 | 单 GPU 分析并发为 1；导出默认也串行，避免资源争抢 | 与具体设备绑定实测，先保证稳定 |
| A-08 | 视频不因模型调用自动传给第三方 AI 服务 | 采用团队自部署的推理流程 |
| A-09 | 用户主动保存编辑；成功后才算已保存，离开有未保存提示 | 首版不实现自动保存和完整撤销栈 |
| A-10 | 本地磁盘保存文件，数据库保存元数据；默认由用户手动删除项目 | 不引入对象存储和复杂保留策略；应显示占用与清理入口 |
