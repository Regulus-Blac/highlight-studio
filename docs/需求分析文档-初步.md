# 通用高光视频剪辑软件需求分析文档

### 1.1 背景

随着短视频、直播录制、生活影像和自媒体内容生产的爆发式增长，用户每天都会产生海量的视频素材。此类视频普遍具备以下特征：

* **时长较长**：包含大量冗余、重复或无价值的过渡画面。
* **精彩分散**：高光片段（情绪张力高、动作激烈、信息密集或美学构图优秀）在时间轴上呈稀疏分布。
* **质量参差**：常伴随镜头抖动、画面模糊、曝光变化、复杂背景或主体尺度变化。

### 1.2 问题陈述

传统的视频剪辑高度依赖人工经验，剪辑师需要花费大量时间进行“粗剪、筛选、精剪、调优、重新构图（横屏转竖屏）”。这在海量视频生产场景下导致了极高的**时间成本和人力成本**。传统的基于简单规则（如固定时长、简单画面变化率、固定静音检测）的自动化剪辑工具，往往无法精准理解复杂的视频语义、事件节奏、音频线索及视觉美感，极易出现漏检、误检以及主体出框等问题。

因此，急需研发一款**基于视频理解大模型与多模态内容分析的通用高光视频剪辑软件**，实现从长视频中自动发现高光帧、智能评估视觉美学与重点、自主推荐并输出符合目标画幅比例（如 16:9 或 9:16）的精准构图框，从而大幅提升通用视频内容生产的自动化与智能化水平。

## 二、术语、数据字典、交互方式与假设依赖

### 2.1 术语表

| 术语             | 定义                                                       |
| -------------- | -------------------------------------------------------- |
| 高光帧            | 被系统判定应进入成片、具备较高信息量、情绪张力、动作激烈程度或美学价值的视频帧。                 |
| 采样帧            | 系统按均匀采样或智能采样策略从原视频中抽取用于模型推理的帧。                           |
| 原视频帧号          | 以原视频解码后的显示帧序列为基准的帧编号，默认 0-based。                         |
| 构图框 / bbox     | 三元组 `[x, y, w]`，表示以原视频显示分辨率为基准的裁剪框左上角坐标与宽度。              |
| targetRatioWH  | 目标画幅比例，格式为 `[w, h]`，当前支持 `[16, 9]` 与 `[9, 16]`。          |
| 连续 IoU 加权 F 分数 | 项目评测指标，记为 `F_video`，综合连续 IoU 与加权 F1 评价高光帧与构图框预测质量。       |
| 显示分辨率          | 考虑旋转元数据后，用户实际看到的视频宽高。                                    |
| 输出模式           | 默认 `highlight_only`，即仅输出高光帧；可选 `all_frames`，用于要求全帧输出时切换。 |
| 运行时功能          | 交付软件在推理/导出阶段执行、用户可感知的功能。                                 |
| 开发流程功能         | 仅模型训练/偏好对齐阶段使用、不随交付软件运行的功能。                              |
| GUI 简单模式       | 面向普通用户的向导式界面，仅暴露高频参数，默认值开箱可用。                            |
| GUI 高级模式       | 面向专业用户的完整参数、日志与批量控制界面。                                   |

### 2.2 输入输出数据字典

#### 2.2.1 输入 JSONL 字段

每行一个 JSON 对象，至少包含以下字段：

| 字段              | 类型         | 必填  | 说明                                 |
| --------------- | ---------- | --- | ---------------------------------- |
| `video_id`      | string     | 是   | 视频唯一标识，输出必须原样回填。                   |
| `video_path`    | string     | 是   | 本地视频文件路径，支持 MP4、AVI、MKV、MOV 等常见格式。 |
| `targetRatioWH` | array[int] | 是   | 目标画幅比例，当前支持 `[16, 9]` 或 `[9, 16]`。 |
| `fps`           | float      | 否   | 视频帧率；缺省时由系统解码读取。                   |
| `width`         | int        | 否   | 原视频显示宽度；缺省时由系统读取。                  |
| `height`        | int        | 否   | 原视频显示高度；缺省时由系统读取。                  |
| `total_frames`  | int        | 否   | 原视频总帧数；缺省时由系统读取。                   |

#### 2.2.2 输出 JSONL 字段

每行一个 JSON 对象，结构如下：

```json
{
  "video_id": "example_001",
  "predictions": [
    {"frame": 10, "bboxes": [120.0, 80.0, 640.0]},
    {"frame": 12, "bboxes": [125.0, 82.0, 640.0]}
  ]
}
```

| 字段                     | 类型           | 说明                                                 |
| ---------------------- | ------------ | -------------------------------------------------- |
| `video_id`             | string       | 与输入一致。                                             |
| `predictions`          | array        | 预测帧列表，按 `frame` 升序排列。                              |
| `predictions[].frame`  | int          | 原视频显示帧号，默认 0-based，必须为非负整数且小于总帧数。                  |
| `predictions[].bboxes` | array[float] | 三元组 `[x, y, w]`，仅输出宽度，高度由评测程序按 `targetRatioWH` 推导。 |

#### 2.2.3 帧号、坐标与取整规则

1. `frame` 默认使用**原视频显示帧号，0-based**。采样帧必须映射回原视频帧号后再输出。
2. `[x, y, w]` 中 `x, y` 为裁剪框**左上角坐标**，`w` 为宽度，均以原视频显示分辨率为基准。
3. `x, y, w` 输出为浮点数，统一保留 2 位小数；内部裁剪取整不改变输出语义。
4. 高度不输出，由系统与评测程序按公式计算：`h = w × target_h / target_w`。内部裁剪时 `h` 四舍五入取整，最小为 1 像素。
5. 坐标必须基于**显示分辨率**，读取视频时应处理旋转元数据。
6. `predictions` 默认仅包含被判定为高光且应进入成片的帧，允许非连续，但必须升序且 `frame` 不重复。若要求全帧输出，通过配置 `output_mode=all_frames` 切换。
7. 无明确主体时，输出整体画面或最大内接目标比例区域；默认优先最大内接区域，避免主体缺失时产生无信息量裁剪。

### 2.3 关键配置项

| 配置项                    | 默认值                        | 说明                                       |
| ---------------------- | -------------------------- | ---------------------------------------- |
| `model_path`           | `./models/highlight_model` | 本地模型路径或模型标识。                             |
| `sample_mode`          | `uniform`                  | 采样模式，支持 `uniform` 与 `smart`。             |
| `sample_fps`           | 1.0                        | 均匀采样帧率；智能采样时作为上限参考。                      |
| `max_frames_per_video` | 3600                       | 单视频最大推理帧数，用于控制显存。                        |
| `output_mode`          | `highlight_only`           | 输出模式，支持 `highlight_only` 与 `all_frames`。 |
| `min_bbox_size`        | 16 px                      | 构图框最小宽度，低于该值触发异常处理。                      |
| `timeout_per_video`    | 30 min                     | 单视频处理超时时间。                               |
| `device`               | `cuda:0`                   | 推理设备，支持 CPU 回退。                          |
| `log_level`            | `INFO`                     | 日志级别。                                    |
| `output_dir`           | `./outputs`                | 输出目录。                                    |
| `allow_empty`          | `true`                     | 是否允许输出空 `predictions`。                   |
| `resume`               | `true`                     | 是否支持断点续跑。                                |

### 2.4 错误码

| 错误码                 | 含义                                       | 默认处理                      |
| ------------------- | ---------------------------------------- | ------------------------- |
| `E_VIDEO_DECODE`    | 视频解码失败或文件损坏                              | 跳过该视频，记录日志，批量继续。          |
| `E_VIDEO_TIMEOUT`   | 单视频处理超时                                  | 终止该视频，记录日志，批量继续。          |
| `E_EMPTY_PRED`      | 输出 `predictions` 为空且 `allow_empty=false` | 跳过该视频并告警。                 |
| `E_FRAME_OOB`       | `frame` 越界或为负                            | 丢弃该帧并记录。                  |
| `E_BBOX_OOB`        | `bbox` 坐标越界                              | 按 4.3 越界策略修正；无法修正则丢弃该帧。   |
| `E_BBOX_INVALID`    | `w <= 0`、`NaN` 或非法数值                     | 丢弃该帧并记录。                  |
| `E_DUPLICATE_FRAME` | 重复 `frame`                               | 保留首次出现，后续重复丢弃并告警。         |
| `E_OOM`             | 显存不足                                     | 降级采样或缩短片段后重试一次；仍失败则跳过并告警。 |
| `E_CONFIG_INVALID`  | 配置缺失或非法                                  | 启动阶段终止并输出明确错误。            |

### 2.5 用户界面与交互方式总览

本软件面向三类用户，交付形态分为 **CLI 主入口**、**本地 GUI 原型** 与 **可选预览视频** 三层，确保非技术用户也能使用核心能力。

| 用户类型                | 交互方式                               | 说明                                       |
| ------------------- | ---------------------------------- | ---------------------------------------- |
| 个人自媒体创作者 / Vlog 爱好者 | GUI 简单模式 + CLI 一条命令                | 通过向导完成导入、比例选择、启动、预览和导出；无需编写代码。           |
| 活动组织方 / 赛事运营团队      | GUI 批量模式 + JSONL + 统计报表            | 表格化管理批量任务，查看逐视频状态、失败重试和统计摘要。             |
| 内容运营与媒体生产团队         | CLI + 配置文件 + Python API + GUI 高级模式 | 配置外置，模块接口清晰，便于接入生产流水线；GUI 高级模式暴露完整参数与日志。 |

交互规则：

1. v1.0 交付以 **CLI + 本地 Web GUI + JSONL + 日志 + 可选预览视频** 为主；GUI 是 CLI 的封装，不得改变 JSONL 输出语义。
2. GUI 默认启动为简单模式，高级参数折叠；所有 GUI 操作应能映射为 CLI 参数或配置文件，便于复现。
3. 所有用户可见错误必须包含错误码、`video_id`、简要原因和处理建议。
4. 批量任务结束必须输出统计摘要：成功数、失败数、空结果数、总耗时、平均单视频耗时。
5. 预览视频与 GUI 预览为可选产物，生成失败不得影响 JSONL 主产物。

### 2.6 假设与依赖

* 输入视频可被 ffmpeg/OpenCV 正常解码；损坏视频按异常用例处理。
* 视频可能无音频轨、含旋转元数据、含可变帧率；系统应兼容或明确降级。
* 模型、依赖包与权重可在本地离线加载，不依赖收费闭源云端 API。
* 项目方或同等标准评测脚本可对输出 JSONL 进行格式校验与 `F_video` 计算。
* 训练/偏好对齐数据与测试数据严格隔离，测试数据仅本地推理使用。
* 评测环境具备单张 NVIDIA A10 24GB 或同等级 GPU；CPU 回退仅保证可运行，不作为性能验收依据。
* GUI 运行于本机浏览器，默认仅监听 `127.0.0.1`，不对外网开放；不依赖公网 CDN。

## 三、目标用户与使用场景

### 3.1 目标用户

1. **个人自媒体创作者 / Vlog 爱好者**：希望快速从数小时的旅行、运动或日常素材中提取精华，生成高质量、可直接分享的短片。
2. **活动组织方 / 赛事运营团队**：需要批量处理体育赛事、户外活动、演出记录、会议培训的录像，快速产出集锦、宣传片或社交媒体切片。
3. **内容运营与媒体生产团队**：需要高效筛选有信息量、情绪张力或商业价值的画面，降低后期制作成本，抢占内容发布时效。

### 3.2 使用场景

* **场景 A：体育赛事与户外运动集锦生成**。长达数小时的比赛录像自动提取精彩进球、对抗瞬间，并智能锁定运动员或运动器材生成 9:16 竖屏短视频。
* **场景 B：Vlog / 旅行生活记录自动化剪辑**。过滤冗余空镜头，保留互动、风景变换或情绪高潮片段，自动完成画面重构。
* **场景 C：课堂讲座与会议培训精华提炼**。结合多模态语义分析，剔除冗长无意义的讨论，精准识别核心讲解、演示画面及关键帧。

### 3.3 应用范围边界

**支持范围**：

* 常见消费级视频：MP4、AVI、MKV、MOV；分辨率 480p～4K；帧率 15～60fps；时长 1 分钟～4 小时。
* 含/不含音频轨；含旋转元数据；恒定帧率优先，可变帧率尽力兼容。
* 目标画幅比例：`[16,9]` 与 `[9,16]`。

**暂不支持范围（v1.0 明确排除）**：

* VR/360° 全景视频、8K 及以上超高清视频。
* 直播流实时输入、多路视频同步剪辑。
* 需要专业色彩管理（HDR/Log）的影视级素材。
* 自动字幕、卡点音乐、特效包装、专业调色。

超出支持范围的输入应给出明确提示，不静默产生错误结果。

| 高级模式 | 内容/媒体团队 | 完整参数、日志、等效 CLI、配置快照 | 无                 | 配置校验、导出报告、复现命令 |

#### 3.4.6 需求优先级依据

* **高优先级**：来自高频核心任务（导入、启动、进度、预览、导出）和核心价值（高光选择与构图），直接决定可用性。
* **中优先级**：来自效率与信任提升（片段微调、错误中心、批量重试、预览成片），显著改善体验但不阻塞主流程。
* **低优先级**：来自高级配置与锦上添花能力（主题、快捷键自定义、多语言），可在后续版本迭代。

### 4.1 输出范围与高光帧规则

1. 默认 `output_mode=highlight_only`：`predictions` 仅含高光且应进入成片的帧。
2. 允许非连续，但必须按 `frame` 升序且不重复。
3. 要求全帧输出时，切换 `output_mode=all_frames`。
4. 空 `predictions`：`allow_empty=true` 时输出空列表；`false` 时跳过并记录 `E_EMPTY_PRED`。
5. 高光片段聚合仅用于预览与物理导出，不改变 JSONL 默认语义。
6. GUI 中的片段勾选、排序、时长微调仅影响成片导出与预览，不修改已导出的 JSONL，除非用户显式点击“重新导出 JSONL”。

### 4.2 越界与异常处理矩阵

| 异常类型             | 检测规则                              | 默认处理动作                | 日志字段                                          | 终止当前视频 |
| ---------------- | --------------------------------- | --------------------- | --------------------------------------------- | ------ |
| 视频解码失败           | ffmpeg/OpenCV 无法打开或读取             | 跳过，批量继续               | `video_id`, `E_VIDEO_DECODE`, 原因              | 是      |
| 单视频超时            | 超过 `timeout_per_video`（默认 30 min） | 终止该视频，批量继续            | `video_id`, `E_VIDEO_TIMEOUT`, 耗时             | 是      |
| `frame` 越界       | `frame < 0` 或 `>= total_frames`   | 丢弃该帧                  | `video_id`, `frame`, `E_FRAME_OOB`            | 否      |
| 重复 `frame`       | 同一 `frame` 多次出现                   | 保留首次，后续丢弃并告警          | `video_id`, `frame`, `E_DUPLICATE_FRAME`      | 否      |
| `w <= 0` 或 `NaN` | 非有限数或宽度非正                         | 丢弃该帧                  | `video_id`, `frame`, `bbox`, `E_BBOX_INVALID` | 否      |
| `bbox` 越界        | `x<0`、`y<0`、`x+w>W`、`y+h>H`       | 平移→等比缩小→仍不满足最小尺寸则丢弃   | `video_id`, `frame`, 原框, 修正框, `E_BBOX_OOB`    | 否      |
| 空 `predictions`  | 列表为空                              | 按 `allow_empty` 输出或跳过 | `video_id`, `E_EMPTY_PRED`                    | 视配置    |
| 显存不足             | 捕获 OOM                            | 降级重试一次，仍失败则跳过         | `video_id`, `E_OOM`, 显存峰值                     | 是      |
| 配置非法             | 启动校验失败                            | 终止启动并输出明确错误           | `E_CONFIG_INVALID`, 字段                        | 整体终止   |
| GUI 路径非法         | 路径不存在/无权限/非视频目录                   | 即时提示，禁止启动             | 字段, 原因                                        | 当前操作阻止 |

### 4.3 越界裁剪策略

设显示宽高 `W, H`，目标比例 `target_w:target_h`，候选框 `[x, y, w]`，`h = round(w × target_h / target_w)`。

1. **优先平移**：若 `w <= W` 且 `h <= H`，将 `x` 限制在 `[0, W-w]`，`y` 限制在 `[0, H-h]`。
2. **再等比缩小**：若 `w > W` 或 `h > H`，令 `scale = min(W/w, H/h)`，更新 `w = w × scale`，重算 `h`，再平移。
3. **最小尺寸检查**：修正后 `w < min_bbox_size` 或 `h < 1`，丢弃并记录 `E_BBOX_INVALID`。
4. **无主体默认框**：输出最大内接目标比例区域；无法确定时输出以画面中心为中心的最大内接区域。

### 4.4 GUI 原型界面需求

#### 4.4.1 形态与设计原则

1. **形态**：v1.0 推荐 **本地 Web GUI**（浏览器访问 `http://127.0.0.1:<port>`），后端复用 CLI 推理服务；可选后续封装为桌面壳（Tauri/Electron）。不依赖公网 CDN，不默认对外网开放。
2. **定位**：GUI 是 CLI 的封装，所有任务最终生成等效 CLI 命令与配置快照；GUI 不改变 JSONL 语义、坐标规则和异常处理规则。
3. **模式**：默认简单模式；高级模式可切换，切换不丢失已填参数。
4. **语言**：默认简体中文；术语与错误码保留英文标识，便于检索。
5. **原则**：高频操作不超过 3 步；默认值开箱可用；错误提示含原因与建议；长任务非阻塞；任何破坏性操作需确认。

* 简单模式：目标比例、采样模式（均匀/智能）、输出模式（仅高光/全帧）、输出目录。

#### 4.4.6 GUI 功能规则补充

1. F-10 项目创建页必须支持“生成等效 CLI 命令”，并在复制时包含输入、输出、模型路径和关键参数。
2. F-11 配置校验必须在用户输入时即时执行，不得等到启动后才报错；校验规则与 2.3 一致。
3. F-12 任务控制必须区分“取消当前视频”和“取消整个批量”，取消整个批量需二次确认；已成功视频默认不重复处理。
4. F-13 预览页的构图框叠加必须基于显示分辨率；比例切换仅改变预览裁剪展示，不修改 JSONL。
5. F-14 导出成片与导出 JSONL 必须分离；重新生成 JSONL 需显式勾选并提示会覆盖或另存。
6. F-15 错误中心必须与 2.4 错误码一一对应，不得出现未定义错误码。
7. F-16 新手引导可跳过，跳过状态本地保存；设置修改不得影响正在运行的任务。

### 5.3 易用性与人机交互

* 支持标准 JSONL 索引与常见视频格式，无需复杂环境预配置。
* GUI 提供简单/高级模式；简单模式高频操作不超过 3 步；高级模式参数分组并即时校验。
* 日志包含 `video_id`、阶段、耗时、显存、错误码、异常摘要；用户可见错误含处理建议。
* 配置外置：模型路径、采样参数、输出目录、超时时间通过配置文件、CLI 或 GUI 设置。
* 批量结束输出统计摘要；预览视频与 GUI 预览为可选产物。
* 可访问性：键盘可完成主流程；对比度满足 WCAG AA；图标有文字标签。

### 5.4 约束与兼容性

* **软件环境**：Linux Ubuntu 20.04/22.04；Python 3.10+（若使用 3.8 需验证模型套件兼容性）；PyTorch、Transformers、ModelScope 等。
* **硬件**：评测推荐单张 NVIDIA A10 24GB；最低显存由模型选型确定并写入 README；CPU 回退仅保证可运行。
* **GUI 环境**：Chrome/Edge/Firefox 近两个大版本；默认监听 `127.0.0.1`；不依赖公网 CDN。
* **离线运行**：支持本地模型缓存与离线加载；模型与依赖许可证在 README 说明。
* **安全合规**：测试数据仅本地推理，严禁上传未授权公开平台、第三方商业云端 API 或公开仓库；GUI 日志默认脱敏路径。

### 5.5 可靠性

* 单视频超时、解码失败、OOM 不得导致批量整体崩溃。
* 支持断点续跑；输出采用临时文件+原子替换，避免半行 JSONL。
* 配置非法在启动阶段终止并明确报错；GUI 任务运行中关闭页面需提示。
* GUI 后端异常不得导致已导出 JSONL 损坏。

### 5.6 可观测性

* 日志字段：时间、级别、`video_id`、阶段、耗时、显存峰值、错误码、异常摘要。
* 批量统计：成功数、失败数、空结果数、总耗时、平均单视频耗时、`F_video`（若评测可用）。
* GUI 提供日志/错误中心，支持筛选、复制、打开输出目录、失败重试。
* 关键阶段支持进度日志或进度条；GUI 进度延迟 ≤ 2 秒。

### 5.7 可维护性

* 模型、采样器、后处理器、导出器模块接口清晰，允许替换模型不改主流程。
* 配置与代码分离；错误码集中定义；JSONL Schema 校验函数独立可测试。
* GUI 与 CLI 共享同一任务服务层，避免两套逻辑；GUI 操作生成等效 CLI 命令。
* 提供 `requirements.txt` 或 `environment.yml`，锁定关键依赖版本。

## 六、边界与范围外事项

* **范围外 1（闭源商业 API）**：核心推理不调用收费闭源云端大模型 API，专注开源本地多模态架构。
* **范围外 2（商业特效包装）**：不包含自动字幕、卡点音乐、专业调色等泛娱乐后期功能。
* **范围外 3（直播实时剪辑）**：不提供直播流实时高光切片与推流能力。
* **范围外 4（超范围视频）**：VR/360°、8K+、HDR/Log 专业素材不在 v1.0 支持范围。
* **范围外 5（多路同步）**：不支持多机位同步剪辑与多视频轨道合成。
* **范围外 6（云端协作）**：不提供多用户云端项目协作、账号体系与在线分享。

## 七、验收标准

### 7.1 格式验收

1. 输出为合法 JSONL，每行结构符合 `{ "video_id": "...", "predictions": [{"frame": 10, "bboxes": [x, y, w]}, ...] }`。
2. JSON Schema 校验通过率 100%；无越界、无 `NaN`、无无效字段、无重复 `frame`、无 `w <= 0`。
3. `predictions` 按 `frame` 升序；`frame` 为 0-based 原视频显示帧号。
4. GUI 导出 JSONL 与 CLI 导出 JSONL 在同一输入、同一配置下语义一致。

### 7.2 正确性与性能验收

1. 项目方或同等标准评测脚本全量跑通，输出 `F_video`。
2. `F_video >= B`，`B` 为项目基线或团队锁定基线（P-07）。
3. 满足 P-01～P-11、T-01～T-09 的初始目标值；若实测偏差，需书面锁定“实测基线 + 偏差说明”，且不低于初始目标 80%。
4. 批量含异常样本时无整体中断、无整体 OOM。

### 7.3 可复现性验收

1. 提供代码仓库、`requirements.txt`/`environment.yml`、模型加载指引、推理脚本。
2. 一条端到端命令复现；固定随机种子、锁定依赖版本、记录模型校验和。
3. README 明确数据目录、模型目录、输出目录、运行命令与常见错误处理。
4. GUI 每个任务可查看等效 CLI 命令与配置快照，便于复现。

### 10.2 迭代轮次与产出演进

* **第一轮（草案）**：生成背景、功能与输入输出说明。采纳 `targetRatioWH`、`[x,y,w]` 换算规则；人工补充非功能需求与验收标准。
* **第二轮（完善）**：增加优先级、边界范围；将 SFT、SAM、DPO/GRPO 转化为 F-03/F-04/F-05；否决“全网一键分发”等无关外延功能。
* **第三轮（工程化）**：补数据字典、异常矩阵、越界策略、验收用例、追踪矩阵；F-05 明确为离线优化；弱化 F-02 具体算法名。
* **第四轮（六维评审）**：量化 P-01～P-08 性能指标；新增 2.5 人机界面、5.2 时间相关需求、3.3 应用范围边界；追踪矩阵增加“来源依据”列；F-05 标注“开发流程”类别；增加 7.4 用例与指标关联、附录 C 自检表；消除“可”类模糊措辞。
* **第五轮（GUI 与用户分析）**：新增 3.4 用户需求分析（画像、任务、旅程、界面模式差异、优先级依据）；新增 4.4 GUI 原型界面需求（页面 G1～G7、状态、线框、规则）；新增 F-10～F-16、P-09～P-11、T-07～T-09、AC-16～AC-22。

### 10.3 关键结论人工核实

* **核实点 1（坐标换算）**：输出 `[x,y,w]`，高度由评测按 `targetRatioWH` 推导，不重复输出 `h`。已在 2.2.3、F-06 校准。
* **核实点 2（核心指标）**：`F_video` 为视频平均连续 IoU 加权 F 分数。已在 5.1 P-07 与 7.2 定义。
* **核实点 3（输出范围）**：默认仅高光帧，支持 `all_frames` 切换；开发前需按项目方评测脚本再次确认。
* **核实点 4（性能目标）**：P-01～P-11 为初始目标，需在目标硬件实测校准；验收允许“实测基线 + 偏差说明”，但不得低于初始目标 80%。
* **核实点 5（人机界面）**：v1.0 以 CLI + 本地 Web GUI + JSONL + 日志 + 可选预览为主；GUI 是 CLI 封装，不改变 JSONL 语义。
* **核实点 6（GUI 形态）**：GUI 默认仅监听 `127.0.0.1`，不依赖公网；简单模式面向普通用户，高级模式面向团队；GUI 必须生成等效 CLI 命令以便复现。
