后续 v1.0 开发按 [baseline应用开发计划书](baseline应用开发计划书.md) 的 M0～M4/L1 阶段和验收标准执行，技术边界见 [架构与发布设计](architecture.md)：首先交付网页＋云端推理及渲染，用户明确要求时单独交付复用网页与契约的本地模式。

1. 契约冻结（ABDE）：在现有 v1 预测契约基础上，确认上传文件标识、异步任务状态、进度、错误、预览与导出接口，以及服务端视频路径和原视频元数据来源。先补充 `contracts/` 再实现。
2. Mock 产品闭环（D/E）：实现上传 → 创建任务 → 持久化与排队 → 查询状态 → 预览 → 下载，覆盖失败及重启恢复；模拟结果明确标记，不依赖真实权重。
3. 真实模型与导出（A/B/E）：准备完整 F1 组件和环境，通过 GPU worker 及适配器从自有或授权公开视频运行真实推理，再接入视频渲染，交付可播放成片。D 按既定契约接入真实状态和结果。
4. 云端发布验收（ABDE）：绑定代码、比赛提交、模型资产和环境版本，验证模型校验与回退、失败恢复、文件访问、存储保留、并发限制及处理时间；覆盖完整上传到成片流程。
5. 第一版交付（ABDE）：交付需求、架构、数据库、接口、验证报告、部署与演示说明，明确实际模型版本、资源要求及尚存限制；发布方式结合组件许可确认。
6. 按需本地模式（A/B/D/E，对应 L1）：用户明确要求时，完成设备实测、本机服务与相同网页、独立模型包的首次下载或离线导入、本地缓存、版本兼容和回退；单独验收，不将云端发布等同于本地模式已完成。
