# 前端工作台（本地开发）

已保存服务器的演示入口为仓库根目录 `Start-Demo.cmd`，默认读取 `config/demo.json`。页面使用“开始分析”“服务已连接”等文案，隐藏内部引擎代号和服务器地址；演示模式仍明确标记。

本轮对应 baseline 的 **M1 网页与 Mock 流程**及 **M3 的前端对接**，覆盖 F-01、F-08～F-15。页面直接依赖 `contracts/` v1，不使用旧 jobs，不修改模型或比赛子模块。当前工作台已支持本机开发及通过SSH连接器访问远程F1。真实F1两种画幅的既有验收见[验收记录](../../docs/f1-video-inference.md)；模型下载/缓存安装器和通用公网发布尚未交付。2026-11-25本轮范围与分工见[最终改进计划](../../docs/FINAL_IMPROVEMENTS_PLAN_20261125.md)，不重新开发已有编辑/导出功能。

## 启动

在仓库根目录使用 Python 3.11+：

```powershell
python -m apps.backend.server --port 8000 --runtime runtime/frontend-dev
```

访问 http://127.0.0.1:8000 。前端是原生 HTML/CSS/JavaScript，无 npm 构建步骤、第三方 CDN 或字体依赖。服务通过固定白名单提供页面、样式和脚本。页面直接访问本机同源服务；使用[SSH连接器](../../docs/demo-runbook.md)时，本机回环网页通过加密中继访问远程服务，浏览器不直接SSH。

默认 `mock-v1` 仅验证导入与异步任务，返回空预测，不提供真实高光分析。页面明确标注模拟状态。需要完整 CPU 媒体联调时，先准备 FFmpeg/FFprobe 6.1+ 和 `requirements-media.txt` 中的依赖，再启动：

```powershell
python -m apps.backend.server --port 8001 --runtime runtime/frontend-media --adapter mock-media --allow-mock-media
```

访问 http://127.0.0.1:8001 。该模式按固定规则生成合成高光，始终 `mock=true`。它可以检验媒体处理流程，但不能作为真实模型效果验收。当前 CPU 媒体支持范围由后端检查：固定/变帧率均可进入推理、最多 10 分钟/4K/120 fps、无旋转元数据等，详见 `docs/ab-cpu-preparation.md`。变帧率的精确时间映射及音画同步暂缓处理。浏览器是否能播放原素材还取决于编码，优先使用 H.264 MP4。

## 已实现交互

- 中文工作台、拖拽/文件选择、512 MiB 大小与后缀校验、16:9 / 9:16 比例选择。
- 原始字节传输至本机 uploads 接口，显示实际传输进度；任务推理中展示阶段，不伪造百分比。
- 新建任务使用幂等键。网络中断造成创建结果不明时，刷新及重试继续复用同一键；失败任务重试创建新任务。
- 每 1.5 秒轮询；只对 queued 显示取消；失败、空预测、服务未配置与网络错误有明确提示。
- 浏览器保存最近 20 个任务 ID、文件名、画幅、已应用编辑及导出 ID；恢复时向服务重新查询，不把本地记录当作最终状态。
- 原视频播放、时间跳转、逐帧查看、按服务端 frame_crops 渲染目标裁剪预览；非高光帧显示说明。
- 高光时间轴显示随播放移动的竖线指针，可用鼠标/触控拖动定位；方向键逐帧移动，Home/End 跳到两端。
- 裁剪预览在每段已选高光结束时自动暂停，并保留最后一帧；再次播放进入下一段，最后一段后回到第一段。原始画面保持连续播放。
- 片段选择、起止时间调整。前端验证顺序与范围，提交完整方案，服务端返回的计划作为预览与导出依据。
- MP4 / JSONL 异步导出、状态查询与下载；无已选帧时禁用 MP4；编辑后隐藏旧下载入口，防止误用旧方案。
- 任务记录、运行设置、窄屏布局、键盘焦点、状态提示和减少动画偏好。
- 分析失败或取消后可直接重新选择视频、调整画幅；旧任务仍保留在记录中。不支持的素材会说明原因，不再锁住编辑器或反复重试同一文件。

视频保存在服务的 runtime 目录；浏览器只保存任务摘要及编辑方案。新建剪辑会保留历史任务。任务正在后台执行时刷新页面可恢复查询；导入或编辑提交期间离开会提示。

## 验证

预览布局回归使用真实生成的 1920×1080、1080×1920 和方形视频，分别检查桌面与窄屏下的原片及裁剪预览完整显示：`node tests/preview-layout.cjs`。依赖和 `PLAYWRIGHT_MODULE` 配置与下方浏览器检查相同。

失败恢复回归：`node tests/frontend-recovery.cjs`，覆盖失败/取消后的刷新恢复、更换素材、重新分析入口和历史保留，不调用真实模型。

播放回归：`node tests/frontend-playback.cjs`，使用实际录制的视频检查指针拖动/键盘定位、分离和相邻片段的逐段暂停、单帧高光、取消选择的片段、原片连续播放及窄屏布局。设置 `NO_VIDEO_FRAME_CALLBACK=1` 可验证兼容播放回调缺失的浏览器。

```powershell
node --check apps/frontend/app.js
python scripts/smoke.py
python -m unittest tests.test_integration tests.test_frontend -q
```

浏览器测试依赖 Playwright 与已安装的 Edge（也可设置 `BROWSER_CHANNEL`）；默认连接 `http://127.0.0.1:8000` 的基础 Mock 服务。设置 `PLAYWRIGHT_MODULE` 为已安装的 playwright 模块绝对目录后执行：

```powershell
node tests/frontend.cjs
```

测试先使用真实本机 uploads/tasks 验证导入、刷新恢复和任务记录，再使用明确的媒体契约夹具验证：创建响应丢失时复用幂等键、推理阶段、片段合法性校验、裁剪预览、导出请求、实际 HTTP 文件下载、编辑及导出恢复、空选集和 390px 布局。生成的视频、截图和下载验证文件均保存于被 Git 忽略的 runtime。媒体夹具测试不代表实际 FFmpeg 渲染或真实模型已通过验收。

本机缺少比赛子模块时，`python scripts/check_repository.py` 会报告缺失；这不阻止前端 Mock 联调。前端开发不自动拉取私有比赛源码或下载模型。


## 本地交互优化（2026-10-30）

基础 Mock 完成后不再请求依赖媒体工具的预览接口，时间轴与导出区会解释当前模式的限制；运行设置提供模式说明。选定视频后可以通过“更换素材”重新选择，任务建立后入口锁定。重新连接前会保护尚未应用的编辑，恢复期间禁止重复切换任务。播放时间按百分之一秒统一进位，避免显示 00:60.00。


## 运行方式选择（2026-11-01）

工作台默认展示云端处理；直接启动本机服务且没有deployment远程信息时，云端入口仍显示待接入。通过connect_demo.py连接后，页面按deployment/model/ready识别远程F1或远程模拟并允许对应任务。本机真实模式仍需手动配置就绪服务。模型下载、设备检测和缓存管理未实现，不因远程连接已接通而宣称可用。当前条件与分工见[运行方式交接](../../docs/frontend-execution-modes.md)。
