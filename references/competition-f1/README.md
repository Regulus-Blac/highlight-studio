# F1 比赛源码参考（供 ABDE 浏览）

产品仓库成员可以直接浏览此目录，无需访问私有比赛仓库或初始化子模块。此处是固定源码参考，不是产品运行时导入的目录；算法改动仍在原比赛仓库维护，产品通过 `services/model_adapter/` 接入。

- `src/`：F1 正式比赛交付包从 `df03d1bcba3f8a4d128d197ce7cc9775d8ac7451` 导出的源码和配置。
- `historical/`：交付包中锁定的历史源码和固定配置，来自多个历史提交。
- [`SOURCE_MANIFEST.json`](SOURCE_MANIFEST.json)：129 个文件的来源、大小和 SHA256；保留原始字节。F1 成绩所对应的源码标签指向 `39337b84ee81428b680f4907ea4cbab0864ac653`。产品的 `vendor/competition` 仍由 `model.lock.json` 管理，两者用途不同。

这里不包含模型权重、测试视频、预测结果、历史特征或运行凭据。目录中的研究脚本可能保留当时的机器路径；它们用于阅读和追溯，不是产品部署说明。

## 为什么有源码还不能直接处理一条新视频

比赛交付包提供了阶段代码和命令，但一些命令的输入已经是特征、概率或前一版的预测，而不是 MP4。比如 [`research_crop_scale_apply.py`](src/scripts/plan_c/research_crop_scale_apply.py) 将 F1 二维裁剪头应用到固定 X1 父预测和双路特征。它不是任意视频的入口，也不能用原比赛预测替代新视频的计算。

| 项目 | 比赛源码提供了什么 | 产品接入还需要什么 |
| --- | --- | --- |
| 模型 | 结构、训练/读出代码、部分固定配置和校验信息 | 在目标 GPU 主机备齐实际权重和固定 processor，确认环境能加载 |
| 媒体 | 处理逻辑和数据接口 | 用有权使用的新视频验收；上线时视频由用户上传，比赛测试视频无需复制 |
| 命令 | 研究阶段的命令和历史复现入口 | 把四阶段串成只依赖本次上传视频和固定模型资产的产品 recipe，返回 v1 结果 |

产品中的 [`f1_runner.py`](../../services/model_adapter/f1_runner.py) 已定义四阶段和校验，但没有内置 F1 新视频 recipe。读取源码、下载完权重、成功跑真实推理是三个不同验收点。DE 开发页面和业务流程时可继续使用 `mock-media`；实际 GPU 验收由 AB 完成。
